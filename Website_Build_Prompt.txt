WEBSITE BUILD PROMPT — Multi-Robot Zone Assignment & Coordination Platform
============================================================================

Use this prompt in Antigravity (or any AI web builder) to generate the website.
It is written as a full feature specification, organized in the order a user
would move through the app.

----------------------------------------------------------------------------
PROJECT OVERVIEW
----------------------------------------------------------------------------
Build a web application where a user manages a fleet of robots by drawing
work zones on a map, creating and naming robots, assigning each robot to a
zone by drag-and-drop, and watching the robots carry out their work in a
live simulation. Robots that depend on each other's output (for example, one
robot collecting water waste and another robot that needs water to plant
trees) must detect that dependency and coordinate automatically, prompting
the user to assign a transport robot when needed. Behave like a real
industrial fleet-management dashboard, not a toy demo — polished, clear, and
professional throughout.

----------------------------------------------------------------------------
1. LOGIN / AUTHENTICATION
----------------------------------------------------------------------------
- A login page (email + password, or a simple demo login) gates access to
  the dashboard.
- Include a "Sign up" option for new users and a "Forgot password" link
  (can be a placeholder flow for now).
- After login, take the user to a short onboarding/instruction screen
  before the main dashboard.

----------------------------------------------------------------------------
2. ONBOARDING / INSTRUCTIONS SCREEN
----------------------------------------------------------------------------
- Show a friendly robot mascot/character that walks the user through how to
  use the app, step by step:
    1. "Draw the areas where work needs to be done."
    2. "Create a robot and give it a name."
    3. "Drag your robot onto a work zone to assign it."
    4. "Watch the robot travel to the zone and start working."
    5. "If robots depend on each other, you'll be asked to connect them."
- Include a "Skip" button and a way to reopen these instructions later from
  a help/menu icon.

----------------------------------------------------------------------------
3. MAP / ZONE PLOTTING
----------------------------------------------------------------------------
- The main workspace is an interactive canvas/map (grid or satellite-style
  background) where the user can draw/plot shapes to mark work zones.
- Drawing tools: freehand or polygon/rectangle draw tool to outline a zone,
  plus the ability to move, resize, or delete a zone after drawing it.
- After drawing a zone, open a form so the user can define that zone's
  work order:
    - Zone name (e.g. "North Field", "Water Tank Area")
    - Task type (e.g. Water Waste Management, Tree Planting, Cleaning,
      Delivery, Inspection — extendable list)
    - Task difficulty / hardness level (Easy / Medium / Hard, or a 1–10
      scale) — harder tasks should take longer and drain more battery
    - Task time limit / deadline (the work must be completed within this
      time; show a countdown once a robot starts working)
    - Resource requirement (e.g. how much water, material, or capacity the
      task needs)
- Each zone shows its current status on the map at all times: Unassigned,
  Assigned, In Progress, Completed, or Overdue (color-coded).

----------------------------------------------------------------------------
4. ROBOT CREATION
----------------------------------------------------------------------------
- A "Create Robot" panel/button lets the user:
    - Name the robot
    - Choose a robot type/role (e.g. Water Collector, Planter, Transporter,
      Cleaner, General Purpose)
    - Set or auto-generate starting stats: battery level (0–100%), health
      (0–100%), speed, and load/resource capacity
- New robots appear in a "Robot Fleet" sidebar/panel as idle icons, ready to
  be assigned.

----------------------------------------------------------------------------
5. ASSIGNING ROBOTS BY DRAG-AND-DROP
----------------------------------------------------------------------------
- The user drags a robot icon from the fleet panel and drops it onto a
  drawn zone on the map to assign it to that zone's task.
- Once dropped:
    - The robot's icon animates moving from its current position to the
      zone on the map (this is the same "go to the assigned spot and start
      working" behavior as a robot vacuum cleaner: it doesn't teleport, it
      travels there, then begins the job).
    - When it arrives, its status changes to "Working," and a progress bar
      tied to the zone's time limit begins counting down.
    - Battery and health decrease gradually while working, at a rate tied
      to the task's difficulty level.
- Each zone should enforce its execution limit: if the robot doesn't finish
  before the deadline, mark the zone "Overdue" and alert the user; if the
  robot's battery/health drops too low mid-task, pause the task and prompt
  the user to send a replacement or recall the robot for charging/repair.

----------------------------------------------------------------------------
6. ROBOT HEALTH, CHARGE, AND RESOURCE MANAGEMENT
----------------------------------------------------------------------------
- Every robot has a persistent status card showing:
    - Battery % (with a low-battery warning threshold)
    - Health % (degrades slowly with use, faster on harder tasks)
    - Current task and zone (if any)
    - Resource load (how much it's currently carrying, out of its capacity)
- Include a "Charging Station" area on the map. Low-battery robots can be
  manually recalled there, or auto-recalled below a critical threshold; show
  a charging animation and a battery bar filling up over time.
- A fleet-wide resource management panel should summarize: total robots,
  idle vs. working vs. charging vs. failed, total zones completed, and
  average fleet health/battery — like a control-room overview.

----------------------------------------------------------------------------
7. MULTI-ROBOT COORDINATION (KEY FEATURE)
----------------------------------------------------------------------------
This is the centerpiece feature and should be built carefully:

- The system must detect when one robot's task produces something another
  robot's task needs. Example (use this exact scenario as the reference
  case): a robot assigned to "Water Waste Management" collects waste water
  as output; a separate robot assigned to "Tree Planting" requires water as
  an input resource.
- When this dependency is detected, the app should NOT move the resource
  automatically on its own — instead, it should prompt the user:
     "Robot A has collected water waste. Robot B (Tree Planting) needs
      water. Assign a robot to transport the water from Robot A's zone to
      Robot B's zone?"
  with an "Assign Transport Robot" action that lets the user drag an
  existing idle robot (or create a new one) to handle the transfer.
- Once a transport robot is assigned, animate it moving between the two
  zones, carrying the resource, and show both source and destination robots'
  resource bars updating as the transfer happens.
- This same pattern should generalize to any two task types that have a
  producer/consumer relationship, not just the water example — design the
  dependency system so new task types can declare "produces X" / "requires
  X" and the app automatically flags the match.

----------------------------------------------------------------------------
8. LIVE SIMULATION & ROBOT-TO-ROBOT COMMUNICATION VIEW
----------------------------------------------------------------------------
- Include a live simulation view (can be a toggleable panel or a dedicated
  tab) that visualizes the robots working in real time on the map.
- Add a "Network View" styled like a Cisco-style network topology diagram:
  each active robot is a node, and lines connect robots that are currently
  communicating or coordinating (e.g. the waste-water robot linked to the
  transport robot linked to the tree-planting robot).
- On these connection lines, show small live message bubbles or a scrolling
  log of the actual "conversation" between robots, for example:
     Robot A -> Robot C: "500L water waste ready for pickup at Zone 2."
     Robot C -> Robot A: "En route, ETA 45s."
     Robot C -> Robot B: "Delivering 500L water, arriving in 90s."
     Robot B -> Robot C: "Confirmed, storage ready."
- This log should update live as the simulation runs, so the user can watch
  the robots negotiate and coordinate step by step, not just see the end
  result.

----------------------------------------------------------------------------
9. GENERAL BEHAVIOR REFERENCE (LIKE A ROBOT VACUUM CLEANER)
----------------------------------------------------------------------------
Use this as the mental model for how a single robot behaves once assigned,
similar to a Samsung robot vacuum:
   1. Robot is idle at its home/base position.
   2. User assigns it to a work zone.
   3. Robot travels from its current position to the zone (visible motion,
      not an instant jump).
   4. On arrival, it begins working, shown by a status change and a
      progress indicator.
   5. It works until the task is done, paused (low battery/health), or the
      time limit expires.
   6. On completion, it returns to idle (or heads to its next assignment,
      or to the charging station if battery is low).
The key difference from a single vacuum cleaner is that THIS platform must
also handle multiple robots whose tasks depend on each other, requiring the
coordination and communication behavior described in Sections 7 and 8.

----------------------------------------------------------------------------
10. OVERALL STYLE / QUALITY BAR
----------------------------------------------------------------------------
- Professional, clean, dashboard-style UI (think fleet-management or
  industrial IoT control panels), not a childish or overly playful look
  outside of the onboarding mascot.
- Smooth animations for robot movement, working states, and resource
  transfers — avoid instant jumps or static state changes.
- Responsive layout: map/dashboard as the main focus, with side panels for
  the robot fleet, zone details, and the coordination/communication log.
- Color-code statuses consistently across the whole app (e.g. green =
  working/healthy, yellow = low battery/warning, red = failed/overdue,
  gray = idle).

----------------------------------------------------------------------------
END OF PROMPT
